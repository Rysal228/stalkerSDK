# Цикличные заказы Сыча на нашивки — IX-Ray 1.3.4

Аддон `rysal-owl-patch-quests` добавляет на «Скадовск» шесть
повторяемых заказов Сыча на трофейные нашивки. Для работы требуется
отдельный установленный мод `rysal-faction-patches`.

## Заказы и выплаты

| Группировка | Нашивок | Выплата за партию |
|---|---:|---:|
| Бандиты | 5 | 500–2000 руб. |
| Одиночки | 5 | 1000–3000 руб. |
| Свобода | 5 | 1500–4000 руб. |
| Долг | 5 | 2000–5000 руб. |
| Наёмники | 5 | 3000–7000 руб. |
| Монолит | 5 | 5000–10000 руб. |

Награда выбирается **заново при каждой сдаче пяти нашивок**, с шагом
**100 рублей**, обе границы включены. Например, за бандитов могут выпасть
500, 600, ..., 2000 рублей. Это не обещание точной суммы при взятии:
интервал указывается и в диалоге, и в описании задачи КПК.

### Как избежать двойной выплаты

В `configs/misc/mod_task_manager_owl_patches.ltx` удалены **все**
`reward_money`: менеджер заданий больше не выдаёт фиксированную награду.

`scripts/rysal_owl_patch_quests.script` в обработчике `turn_in`:
1. проверяет, что заказ активен, не сдан и у игрока есть 5 нашивок;
2. передаёт Сычу **ровно пять** соответствующих предметов;
3. выбирает `math.random(min_reward / 100, max_reward / 100) * 100`;
4. начисляет деньги **один раз** через штатную
   `dialogs.relocate_money_to_actor`, которая обновляет денежную
   статистику и показывает стандартное уведомление о деньгах;
5. устанавливает инфопоршень `*_done`, чтобы закрыть задачу КПК.

Когда задача закроется, можно взять её снова. Флаг `done` сбрасывается
**только при принятии нового цикла**, чтобы прежняя задача успела
завершиться. Шесть заданий независимы.

Для сохранений, в которых квест уже взят по прежним правилам, новый
обработчик сдачи также применит диапазон наград — новые задачи брать
заново не требуется. Перед обновлением на всякий случай сохрани
резервную копию сохранения.

## Почему диалог работает в IX-Ray 1.3.4

В указанной сборке IX-Ray `b7f33238c` доступные диалоги считываются
из `CharacterInfo().ActorDialogs()` NPC. Поэтому мы добавляем Сычу
два `actor_dialog` через **XMLOverride профиля**, а не через
инфопоршни игрока:

```xml
<xml>
    <specific_character id="zat_b30_owl_stalker_trader" override="add">
        <actor_dialog>rysal_owl_patch_offer</actor_dialog>
        <actor_dialog>rysal_owl_patch_turn_in</actor_dialog>
    </specific_character>
</xml>
```

Важно: в этой версии XMLOverride атрибут `override="add"` стоит на
родительском `specific_character` и вставляет дочерние узлы.
Алгоритм ищет элемент по имени тега, а не по `id`, поэтому для других
модификаций/переставленных NPC требуется проверка порядка профилей
(в текущем STCOP пользователь уже подтвердил работу).

## Установка

Скопируй обновлённую **всю папку**
`ixr_addons/rysal-owl-patch-quests/` рядом с
`ixr_addons/rysal-faction-patches/`. Перезапусти игру.

Оригинальную `gamedata` и профили Сыча внутри STCOP вручную менять
**не нужно**. Сохраняются две реплики Сыча: выбор заказов и сдача
принесённых нашивок; существующие реплики и квесты Бороды не затронуты.

## Тестирование

1. Взять у Сыча бандитский заказ, прочитать диапазон 500–2000 в КПК.
2. Принести **пять** нашивок бандитов и записать количество денег до
   разговора. Проверить, что изъято ровно пять и начислена сумма внутри
   диапазона с шагом 100, без дополнительных 2000 рублей сверху.
3. Дождаться завершения задачи в КПК и **взять такой же заказ повторно**.
   Сдать следующие пять и проверить независимый выбор суммы.
4. Проверить Монолит (5000–10000), сохранение/загрузку и обычные
   задания Сыча.
5. В логе можно искать `[Rysal Owl] delivered <группировка>, paid <сумма>`.

Код проверен статически по текущим конфигам и исходникам
IX-Ray 1.3.4. **Игровая проверка рандомизации ещё не выполнена**.
